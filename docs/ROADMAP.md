# Roadmap and milestones

The order is deliberate: first the foundation and the core needed for the master's thesis (outcome by the end of the semester: literature review, knowledge base + evaluation dataset, CAD analysis prototype), then the SaaS platform around it. Each milestone = separate `feat/<module>-…` branches and PRs to `main`.

| MS | Name | Scope | Acceptance criteria |
|---|---|---|---|
| **M0** | Foundation | monorepo (`uv` + `pnpm`), `justfile`, pre-commit, lint/types/import-linter, skeletons of 4 services with `/healthz`, `deploy/compose` (Postgres+pgvector, S3/SQS emulator, LiteLLM with a fake provider, Langfuse, `grafana/otel-lgtm`, Ollama optional), OTel in the skeletons, GitHub Actions (PR pipeline), Renovate/Dependabot, PR/issue templates | `just up && just smoke` passes locally (healthz + trace in Tempo); CI green on a PR |
| **M1** | Domain core | `bom-core` (model, JSON Schema, value and unit normalization, grouping), `cad-parsers` with the **KiCad** plugin (+ CSV BOM), `rules` (rule pack v1: schematic, ranges, footprint↔enclosure, IEC 60601 checklist as flags for review), `eval` (item precision/recall/F1, field accuracy, hallucinations, cost); fixtures per `docs/thesis/ZBIOR_EWALUACYJNY_KANDYDACI.md` | unit tests ≥ 85% coverage; the KiCad parser passes the fixtures; the `bomagent parse` and `bomagent eval` CLIs work |
| **M2** | Knowledge base | `kb` + `kb-indexer`: PDF ingest (Docling), chunking, embeddings through the gateway, hybrid vector + FTS, reranker, global/tenant scopes with RLS, KB snapshot | retrieval tests (recall@k on a small dataset), KB isolation tests |
| **M3** | Agents – variants A and B | `llm` (gateway client, closed/open-weight model catalogue), `agents` (versioned prompts), runtimes `langgraph_a`, `langgraph_b`, `claude_agent_sdk_a` behind `VariantRuntime`, `agent-worker` (SQS), budgets, fan-out, structured output, checkpoints | an A and B run on the KiCad fixture with a fake LLM yields a BOM; step trace in Langfuse/OTel; CLI `bomagent run --variant A|B` |
| **M4** | SaaS platform – backend | `api`: tenancy, identity (OIDC; locally a mock IdP), RBAC, projects (upload to S3, presigned URL), runs (+SSE), bom (editing → tenant knowledge), audit (hash chain), metering/limits, OpenAPI 3.1 + TS client; `ingest-worker` in a sandbox | contract, integration and **tenant isolation** tests green; audit events for every mutation |
| **M5** | Frontend | `apps/web` per `docs/design/UX_GUIDELINES.md`: shell with the organization switcher, Start, Projects, New run modal, Live run, BOM with the provenance panel, Comparison, Knowledge base, Audit log, Settings (members, SSO, API keys), onboarding; i18n PL/EN | Playwright E2E for the scenarios from `TESTING.md`, axe with no violations, screenshots in the PR |
| **M6** | Infrastructure | `infra/cdk`: stacks network, data, identity, compute, observability, edge, security-baseline; cdk-nag; deploy pipeline (disabled by a flag); runbooks | `just synth` without cdk-nag errors (or with documented exceptions); CDK assertion tests |
| **M7** | Further formats | plugins: IPC-2581, ODB++, EDIF, PDF (schematic/BOM), DXF, DWG (after the licensing ADR), Altium and OrCAD spikes | fixtures and robustness tests for each plugin; limitation messages in the UI |
| **M8** | Thesis experiment | evaluation dataset (open biomedical projects + reference BOMs), matrix {A,B} × {closed, open-weight} × N repetitions, report (tables/charts for chapter 7) | `bomagent experiment run` generates a report in `evals/reports/` |

Every milestone ends with an update of `docs/STATUS.md` (what works, how to run it, what next, known issues).
