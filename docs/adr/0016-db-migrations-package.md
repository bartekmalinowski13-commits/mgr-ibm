# ADR-0016: A single migrations package with hand-written DDL and database roles

Status: Accepted · 2026-11-09 (agent decision, pending acceptance – see `docs/DECISIONS_LOG.md`)

## Context
Four services use a single Aurora PostgreSQL database (ADR-0004). Every tenant table requires RLS policies, and every migration that changes policies requires a security review (SECURITY.md). Autogenerated migrations know nothing about RLS policies or role privileges.

## Decision
- The `packages/py/db-migrations` package (`bomagent_migrations`, foundation layer) contains **all** of the platform's DDL as hand-written Alembic migrations; domain modules keep only table definitions for queries.
- Cluster roles (`bootstrap.sql`): `bomagent_migrator` (object owner, migrations), `bomagent_app` (API and workers), `bomagent_platform` (platform pipelines: global KB, onboarding). None of them has `BYPASSRLS` or `SUPERUSER`.
- Every tenant table: `ENABLE` + `FORCE ROW LEVEL SECURITY`, policies based on `app.current_tenant_id()` (NULL without context ⇒ no rows). A catalog test in the `isolation` suite ensures that a new table with `tenant_id` cannot pass without RLS.
- Migrations are run by a separate task (ECS one-off / `migrate` in compose) with the migrator secret.

## Consequences
A single place to review policies; migrations are code with tests. Cost: no autogeneration – table changes require hand-written DDL.

## Alternatives considered
Per-service migrations (ordering conflicts, scattered policies); autogenerate from SQLAlchemy (no RLS and no grants).
